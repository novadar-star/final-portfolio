AI Job Scraper &
Custom Output Parser

started from a public n8n tutorial, then wrote a custom parser because the AI kept sending back broken JSON. the parser is the part that actually matters.

problem

most n8n job scraper tutorials break the moment the LLM's output isn't perfectly formatted JSON. the AI agents in these workflows have no error handling — they just fail silently or crash the run.

that's fine for a demo. it's not fine for something you actually want to use more than once.

thinking

re-prompting and hoping the model sends cleaner output next time isn't a strategy at scale. the problem isn't the model — it's that there's no fallback when the format is wrong.

most people add a "format as JSON" instruction and call it done. that handles maybe 70% of cases. the other 30% still fail silently.

system

Trigger (Slack) → Scrape (job listings) → Match (AI agent against resume context from Google Drive) → Parse (custom JS: fence-strip → JSON.parse → regex fallback → safe defaults) → Draft (tailored application materials) → Deliver (results back to Slack with match score)

build

built the parser as a Function node in n8n. the logic runs in four stages, each one a fallback for the one before: 

// Stage 1: strip markdown fences if the model wrapped output in ```json ... ```
let raw = $input.first().json.output ?? '';
raw = raw.replace(/^```(?:json)?\s*/i, '').replace(/\s*```\s*$/i, '').trim();

// Stage 2: attempt a clean JSON.parse
try {
  return [{ json: JSON.parse(raw) }];
} catch (_) {}

// Stage 3: regex extraction — pull key-value pairs from malformed output
const extracted = {};
const kvPattern = /"(\w+)"\s*:\s*("(?:[^"\\]|\\.)*"|\d+|true|false|null)/g;
let match;
while ((match = kvPattern.exec(raw)) !== null) {
  try { extracted[match[1]] = JSON.parse(match[2]); } catch (_) {}
}
if (Object.keys(extracted).length > 0) return [{ json: extracted }];

// Stage 4: safe defaults — workflow continues rather than crashing
return [{ json: { match_score: 0, summary: '', skills: [], error: 'parse_failed' } }];

later reused the same parser in a public webinar co-presentation — which meant sanitizing a hardcoded API key from the workflow JSON before sharing. that was a useful lesson about the gap between "works on my machine" and "shareable artifact."

outcome

a reusable parser pattern that's now a standard Function node in every AI-output workflow i build. the job scraper runs reliably on demand via Slack.

the parser has been reused in three other n8n projects since — the GTM outbound pipeline, the attendee confirmation system, and a content categorization workflow.

learning

the parser is more useful than the scraper. the scraper is a tutorial. the parser is a solution to a real recurring problem.

that distinction — between following a pattern and solving a problem — is the one i'm trying to build toward in everything i make.
